# Review of NoT v1 (commit c2a9b42)

Why v2 exists. Every finding marked "confirmed" was reproduced with a Hardhat test against the v1 contracts.

## Architecture

v1 put the whole LMS on-chain: 6 contracts (Identity, CourseManagement, StudentAcademicManager, ExamManagement, GraduationManager, Certificates). Every write needs a wallet signature and gas, reads loop over on-chain arrays, and data can never be deleted.

## Findings

| # | Severity | Finding | Status |
|---|---|---|---|
| F1 | Critical | Student national ID, phone and email stored on a public chain, readable by any address, impossible to delete. Conflicts with Egypt's Personal Data Protection Law (151/2020). | Confirmed |
| F2 | Critical | `ExamManagement.updateExam` has no ownership check: institution B can rename or delete institution A's exam. `submitResult` also does not check the exam belongs to the caller. | Confirmed |
| F3 | Critical | `Identity.addStudents` lets any verified institution attach any student without consent. It can then enroll, grade, approve graduation and issue a certificate to another institution's student. | Confirmed |
| F4 | High | Grades cannot be corrected once set. `updateGrade` recomputes GPA over all courses: 157k gas for the 1st course, 1.03M gas for the 30th. The stored "GPA" is the average score out of 100. | Confirmed |
| F5 | High | `finalizeGraduation` accepts any `certificateId`, including one that does not exist. | Confirmed |
| F6 | High | `ipfsHash` is not IPFS: the frontend stores a JSON string `{degree, graduationDate}` on-chain. There is no document hash, so a verifier cannot tell whether a given PDF is authentic. | Code reading |
| F7 | Medium | Only the platform admin can verify students (`verifyUser`), which does not scale. | Code reading |
| F8 | Medium | Enrollment keys in `StudentAcademicManager` are not scoped by institution (`courseId + semester`), and GPA uses the caller's course credits for all courses. | Code reading |
| F9 | Medium | New users are redirected to `/apply`, which has no route; registration exists only in dev pages. Student and employer dashboards are placeholders. | Code reading |
| F10 | Low | `npm install` fails on a fresh clone (hardhat-network-helpers 3.x needs Hardhat 3). `frontend/node_modules` (4,300 files) and `dist/` are committed. Unused contracts: `Examinations.sol`, `Migrations.sol`, `SecurityUtils.sol`. | Confirmed |

## What v2 keeps

- The idea and the roles (admin, institution, student, employer).
- Admin accreditation of institutions, revocation, emergency pause, public `/verify/:id` page. These move to the small `CredentialRegistry` contract or to the API.
