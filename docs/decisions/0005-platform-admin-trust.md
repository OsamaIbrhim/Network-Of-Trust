# 0005: الـ admin هو أساس الثقة، فبنحرسه بدل ما نثق فيه على العمياني

- **التاريخ:** 2026-09-28
- **الحالة:** مقبول
- **المرحلة:** Phase 1 (قبل Task 6)

## السياق (Context)
بعد ADR 0002 و0004، الـ admin يقدر يضيف موقّع لأي جامعة ويلغي دفعات كاملة. فلو المفتاح بتاعه اتسرق، الحرامي يقدر يضيف محفظته كموقّع لأي جامعة ويصدر شهادات باسمها. ده ناتج مباشر من التصميم، ولازم يبقى مكتوب بوضوح.

## البدائل (Options)

| المعيار | أ: الـ admin يبقى multisig + كل حاجة علنية + تنبيهات | ب: كل جامعة تدير موقّعيها بنفسها |
|---|---|---|
| الصحة والأمان | سرقة مفتاح واحد من الـ multisig مش كفاية، وأي تغيير بيبان في events عامة ويطلّع تنبيه | لو مفتاح الجامعة اتسرق، الحرامي يضيف موقّعين ويشيل الموقّعين الحقيقيين، والجامعة محتاجة الـ admin برضه عشان ترجع |
| البساطة | من غير تغيير في العقد | تصميم أكبر، ولسه محتاج الـ admin في حالة السرقة |

## القرار (Decision)
البديل أ:
1. **multisig إجباري:** الـ admin لازم يتحول لـ multisig (زي 2 من 3) قبل أي نشر حقيقي، والنقل ده متختبر (ADR 0003).
2. **كل حاجة علنية:** كل حاجة الـ admin بيعملها بتطلع event عام على الشبكة.
3. **تنبيهات:** الـ listener بتاع كل جامعة بيطلّع تنبيه لأي `SignerAdded` أو `SignerRemoved` أو `BatchRevoked` مطلبتهاش.
4. صفحة التحقق بتعرض المحفظة اللي وقّعت الدفعة، وإمتى اتضافت (من الـ events).

## ليه (Rationale)
أي نظام شهادات لازم يبقى فيه جهة بتقول "المحفظة دي تبع جامعة المنوفية"، زي الجهة اللي بتصدر شهادات الـ HTTPS للمواقع. المهم إن الجهة دي متبقاش مفتاح واحد، وإن أي حاجة بتعملها تبان للكل.

## التمن (Consequences)
الثقة في المنصة لسه موجودة، بس بقت محدودة ومتراقبة.

## هنعرف إزاي إننا غلطنا
لو جامعة طلبت ضمان إن محدش يضيف موقّع باسمها من غير علمها. وقتها نعمل مهلة إجبارية على `addSigner` (زي 48 ساعة، والجامعة تقدر تعترض فيها)، و`removeSigner` يفضل فوري. ده في عقد جديد، ومكتوب كـ future work.
